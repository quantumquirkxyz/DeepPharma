# Rúbrica y entregables académicos

**Versión:** 0.1
**Fuente principal:** `SRC-01`, `SRC-02`, `SRC-03`
**Estado:** Línea base académica inicial

## 1. Evaluación identificada

| Componente | Peso |
|---|---:|
| Parciales | 35% |
| Asignaciones, investigación y charlas | 30% |
| Proyecto final | 35% |

La calificación oficial corresponde a la profesora y no será sustituida por métricas técnicas internas.

## 2. Proyecto final

| Componente | Puntos |
|---|---:|
| Matriz de trazabilidad | 5 |
| Modelo de casos de uso | 5 |
| Especificaciones de casos de uso | 20 |
| Escenarios de uso y calidad | 5 |
| Prototipos de pantallas | 5 |
| Descripción de arquitectura | 5 |
| Vista de casos de uso: clases, secuencia y colaboración | 25 |
| Vista lógica | 5 |
| Vista de puesta en marcha/despliegue | 5 |
| Casos de prueba | 10 |
| Coevaluación individual | 5 |
| Estructura formal del trabajo | 5 |
| **Total** | **100** |

## 3. Mínimos identificados

- Una matriz de trazabilidad.
- Un modelo general de casos de uso.
- Mínimo seis especificaciones de casos de uso.
- Un caso de uso seleccionado para realización detallada.
- Mínimo dos escenarios del caso seleccionado.
- Mínimo dos diagramas de secuencia.
- Mínimo dos diagramas de colaboración/comunicación.
- Mínimo dos diagramas de clases de diseño.
- Un documento de arquitectura RUP.
- Vista lógica.
- Vista de despliegue o puesta en marcha.
- Casos de prueba.
- Coevaluación por integrante.

## 4. Separación de alcance

### Académico obligatorio

Los elementos de las secciones 1–3 y los mínimos oficiales anteriores.

### Complementario profesional

CI/CD, Docker, MLOps, seguridad avanzada, validadores automáticos, despliegue reproducible, métricas técnicas y sistema multiagente. Estos elementos mejoran el proyecto, pero no sustituyen la rúbrica.

## 5. Criterio de interpretación

Cuando una propuesta técnica entre en conflicto con una instrucción oficial, se conserva la instrucción oficial y se registra la propuesta como alternativa o ampliación.
