# Runbook de incidentes de datos

**Estado:** Requisito operativo aceptado; parámetros institucionales pendientes.

## Flujo

1. Identificar y registrar el incidente con `traceId` o identificador
   equivalente.
2. Contener el acceso, proceso o credencial afectada.
3. Preservar logs, hashes, versiones y evidencia relevante.
4. Determinar datasets, usuarios, entornos y operaciones afectados.
5. Notificar al responsable de datos, seguridad o privacidad correspondiente.
6. Restaurar desde una copia verificada si aplica.
7. Documentar impacto, causa, recuperación y acciones preventivas.

No se eliminan evidencias para “limpiar” el entorno ni se publican datos
afectados en tickets o logs.
