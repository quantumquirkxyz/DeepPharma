# CU-04 — Visualizar y gestionar alertas priorizadas

**Versión:** 0.1
**Estado:** Borrador en refinamiento
**Clasificación:** Caso de uso funcional principal
**Fuente académica:** `SRC-01`, `SRC-05`, `SRC-07`, `SRC-08`

## 1. Objetivo

Permitir que el farmacéutico o administrador de farmacia consulte alertas de desabastecimiento priorizadas, revise su evidencia y registre la gestión realizada.

## 2. Actores

- **Actor principal:** `ACT-02 Farmacéutico`.
- **Actor secundario:** `ACT-05 Administrador de farmacia`.
- **Actor administrativo:** `ACT-01 Administrador del sistema`, según permisos.
- **Fuente de resultados:** `CU-03 Generar predicciones de riesgo`.
- **Servicio relacionado:** `EXT-03 Servicio de correo/notificaciones`, mediante `CU-16`.

## 3. Disparador

El actor accede al dashboard, solicita consultar alertas o selecciona una alerta para revisar su detalle.

## 4. Precondiciones

- El actor está autenticado y autorizado.
- Existen predicciones o el sistema puede informar que no existen.
- El dashboard está disponible.
- Las alertas tienen estado, prioridad y fecha.

## 5. Postcondiciones

### Éxito

- El actor visualiza las alertas permitidas.
- Los filtros aplicados quedan reflejados en el resultado.
- El detalle muestra evidencia y estado de la alerta.
- Una gestión o reconocimiento queda registrado con actor y fecha.
- Una exportación válida produce un archivo identificable.

### Sin resultados

- El sistema informa que no existen alertas para los filtros seleccionados.
- No presenta ausencia de resultados como fallo técnico.

### Fallo

- El sistema informa la causa de indisponibilidad.
- No registra una gestión incompleta como realizada.

## 6. Flujo básico — Consultar alertas

1. El actor accede al dashboard.
2. El sistema verifica los permisos.
3. El sistema recupera las alertas disponibles.
4. El sistema ordena las alertas según prioridad operativa y fecha.
5. El sistema muestra medicamento, centro, nivel, cobertura, fecha y estado.
6. El actor selecciona una alerta o aplica un filtro.
7. El sistema muestra el resultado correspondiente.
8. Finaliza el flujo.

## 7. Flujos alternos

### FA-01 — Filtrar alertas

1. El actor selecciona centro, medicamento, categoría, nivel o estado.
2. El sistema valida los filtros.
3. El sistema actualiza la lista.
4. Si no existen resultados, aplica el resultado sin alertas.

### FA-02 — Consultar detalle

1. El actor selecciona una alerta.
2. El sistema muestra predicción, fecha, modelo, cobertura, variables relevantes y estado.
3. El actor puede regresar a la lista.

### FA-03 — Reconocer o gestionar alerta

1. El actor selecciona una acción permitida.
2. El sistema solicita observación o resultado cuando corresponda.
3. El sistema registra actor, fecha, acción y comentario.
4. El sistema actualiza el estado de gestión.

### FA-04 — Exportar resultados

1. El actor solicita exportar la vista filtrada.
2. El sistema genera un archivo con los datos autorizados.
3. El sistema informa el resultado de la exportación.

## 8. Flujos de excepción

### FE-01 — Sin alertas

1. El sistema muestra un estado vacío explicativo.
2. El sistema permite cambiar los filtros.
3. Finaliza el flujo.

### FE-02 — Datos desactualizados

1. El sistema identifica que la predicción excede su vigencia.
2. Muestra la antigüedad y el estado desactualizado.
3. No presenta el dato como predicción vigente.

### FE-03 — Error de persistencia

1. El sistema no puede recuperar las alertas.
2. Informa que los datos no están disponibles.
3. Registra el error técnico.

### FE-04 — Permiso insuficiente

1. El sistema rechaza la consulta o acción.
2. No revela información no autorizada.
3. Registra el intento cuando corresponda.

### FE-05 — Exportación fallida

1. El sistema informa que no pudo generar el archivo.
2. No presenta una exportación incompleta como válida.

## 9. Reglas de negocio provisionales

- `RN-CU04-01`: una alerta debe referenciar una predicción o condición operativa identificable.
- `RN-CU04-02`: la prioridad visible debe derivarse de reglas aprobadas.
- `RN-CU04-03`: la clasificación operativa no sustituye la salida original del modelo.
- `RN-CU04-04`: la información se filtra por permisos y ámbito del actor.
- `RN-CU04-05`: reconocer una alerta no implica resolver el desabastecimiento.
- `RN-CU04-06`: toda acción de gestión debe conservar actor, fecha y resultado.
- `RN-CU04-07`: una predicción desactualizada debe identificarse explícitamente.

## 10. Requisitos relacionados

- `RF-04` Visualizar alertas priorizadas.
- `RNF-04` Cargar el dashboard dentro del tiempo aprobado `[PENDIENTE DE MEDICIÓN]`.
- `RN-04` Priorizar y proteger la información de alertas.

## 11. Escenarios candidatos

- `ESC-CU04-01` Consultar alertas críticas.
- `ESC-CU04-02` Consultar sin resultados.
- `ESC-CU04-03` Revisar detalle de una alerta.
- `ESC-CU04-04` Reconocer una alerta.
- `ESC-CU04-05` Consultar predicción desactualizada.
- `ESC-CU04-06` Exportar alertas filtradas.

## 12. Criterios de aceptación preliminares

- El farmacéutico puede consultar alertas de su ámbito.
- Las alertas aparecen ordenadas por prioridad definida.
- Los filtros no exponen datos fuera del permiso.
- El detalle conserva la relación con predicción y modelo.
- Las alertas sin resultados se representan como estado vacío.
- Las acciones quedan auditadas.
- Las predicciones desactualizadas se muestran como tales.
- Las exportaciones contienen únicamente datos autorizados.
