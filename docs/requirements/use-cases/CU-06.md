# CU-06 — Evaluar usabilidad del sistema mediante escala SUS

**Versión:** 0.1
**Estado:** Borrador académico en refinamiento
**Clasificación:** Caso de uso académico de validación externa
**Fuente académica:** `SRC-01`, `SRC-05`, `SRC-06`, `SRC-07`

## 1. Nota de alcance

Este caso de uso se documenta para cumplir el mínimo académico de seis especificaciones. Representa una actividad de evaluación del producto, no una funcionalidad operativa principal de DeepPharma.

El MVP no implementará necesariamente un módulo interno para administrar cuestionarios SUS.

## 2. Objetivo

Evaluar la usabilidad del prototipo mediante la aplicación de la escala SUS a usuarios representativos y analizar los resultados para identificar oportunidades de mejora.

## 3. Actores

- **Actor principal:** `ACT-04 Evaluador de usabilidad`.
- **Participantes:** `ACT-02 Farmacéutico`, `ACT-05 Administrador de farmacia`.
- **Artefacto evaluado:** prototipo o MVP de DeepPharma.
- **Herramienta externa:** formulario o mecanismo aprobado para aplicar SUS.

## 4. Disparador

El evaluador inicia la evaluación después de que los participantes hayan utilizado el prototipo durante el período definido.

## 5. Precondiciones

- Existe un prototipo evaluable.
- Los participantes han sido seleccionados y autorizados.
- El instrumento SUS está disponible.
- Se han definido los módulos o tareas a evaluar.
- Se han establecido condiciones de aplicación.

## 6. Postcondiciones

### Éxito

- Se reciben respuestas válidas.
- Se calcula la puntuación SUS.
- Se documentan resultados cuantitativos y observaciones cualitativas.
- Se identifican problemas y recomendaciones.
- El reporte queda disponible para actualizar requisitos, diseño y backlog.

### Datos insuficientes

- Se informa que la muestra o respuestas no permiten una conclusión válida.
- No se presenta el resultado como evidencia concluyente.

## 7. Flujo básico

1. El evaluador define la evaluación.
2. El evaluador selecciona participantes y módulos.
3. El evaluador explica el propósito y condiciones de la evaluación.
4. Los participantes utilizan el prototipo.
5. Los participantes completan el cuestionario SUS.
6. El evaluador recopila las respuestas.
7. El evaluador verifica que las respuestas estén completas.
8. Se calcula la puntuación según la fórmula SUS.
9. Se analizan comentarios y observaciones.
10. Se genera el reporte.
11. Se registran recomendaciones de mejora.
12. Finaliza la evaluación.

## 8. Flujos alternos

### FA-01 — Participante no responde

1. El evaluador identifica la respuesta pendiente.
2. Se envía un recordatorio mediante el mecanismo autorizado.
3. La respuesta queda pendiente o se excluye según el protocolo de evaluación.

### FA-02 — Evaluación por módulo

1. El evaluador separa las tareas o módulos.
2. Se recopilan observaciones específicas.
3. El reporte relaciona hallazgos con cada módulo.

### FA-03 — Comentario cualitativo relevante

1. El evaluador registra el comentario.
2. Lo relaciona con una pantalla, tarea o requisito.
3. Se crea una recomendación o defecto cuando corresponda.

## 9. Flujos de excepción

### FE-01 — Respuesta incompleta

1. El sistema o evaluador identifica campos faltantes.
2. La respuesta se marca como incompleta.
3. Se solicita corrección o se excluye según el protocolo aprobado.

### FE-02 — Muestra insuficiente

1. El evaluador identifica que no se alcanzó la muestra definida.
2. El reporte marca la limitación.
3. No se generalizan los resultados a toda la población.

### FE-03 — Prototipo no disponible

1. La evaluación se suspende.
2. Se registra el bloqueo.
3. Se reprograma cuando exista una versión evaluable.

## 10. Reglas de negocio y evaluación

- `RN-CU06-01`: la escala SUS se calcula con la fórmula estandarizada.
- `RN-CU06-02`: las respuestas incompletas deben identificarse.
- `RN-CU06-03`: la muestra y sus limitaciones deben documentarse.
- `RN-CU06-04`: los resultados no deben presentarse como representativos si la muestra no lo permite.
- `RN-CU06-05`: cada recomendación debe relacionarse con una pantalla, tarea, requisito o defecto cuando sea posible.
- `RN-CU06-06`: la evaluación SUS es externa al modelo funcional principal del MVP.

## 11. Requisitos relacionados

- `RNF-06` Evaluar la usabilidad del prototipo.
- `RF-06` Ejecutar y documentar la evaluación SUS `[ACADÉMICO; no implica módulo operativo]`.
- `QA-01` Registrar evidencia de validación con usuarios.

## 12. Escenarios candidatos

- `ESC-CU06-01` Evaluación SUS completada.
- `ESC-CU06-02` Respuestas incompletas.
- `ESC-CU06-03` Muestra insuficiente.
- `ESC-CU06-04` Hallazgo de usabilidad asociado a una pantalla.

## 13. Criterios de aceptación preliminares

- La evaluación utiliza el instrumento SUS definido.
- La fórmula se aplica correctamente.
- La muestra y las condiciones se documentan.
- Las respuestas incompletas no se ocultan.
- Los resultados incluyen limitaciones.
- Las recomendaciones se convierten en mejoras, defectos o decisiones trazables.
- La actividad no se presenta como módulo implementado si no existe código para ello.
