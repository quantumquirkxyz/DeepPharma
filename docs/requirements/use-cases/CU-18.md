# CU-18 — Administrar usuarios y roles

**Versión:** 0.1
**Estado:** Borrador en refinamiento
**Clasificación:** Caso de uso funcional candidato
**Fuente:** matriz RBAC, `SRC-11`, requisitos de seguridad

## 1. Objetivo

Permitir que un administrador autorizado gestione usuarios, roles y ámbitos de acceso de DeepPharma aplicando mínimo privilegio y trazabilidad.

## 2. Actores

- **Actor principal:** `ACT-01 Administrador del sistema`.
- **Actores afectados:** `ACT-02 Farmacéutico`, `ACT-03 Ingeniero de Machine Learning`, `ACT-04 Evaluador de usabilidad`, `ACT-05 Administrador de farmacia`.
- **Servicio externo:** proveedor de identidad, si se adopta.

## 3. Disparador

El administrador solicita crear, modificar, desactivar un usuario o asignar un rol.

## 4. Precondiciones

- El administrador está autenticado con privilegios suficientes.
- Las políticas de roles están definidas.
- El ámbito de acceso está disponible.

## 5. Postcondiciones

### Éxito

- El usuario o rol queda actualizado.
- Se registra quién, cuándo y qué cambió.
- Los permisos efectivos corresponden a la configuración aprobada.

### Fallo

- La configuración anterior permanece.
- El sistema informa la causa.
- No se produce una asignación parcial no auditada.

## 6. Flujo básico

1. El administrador accede a la administración de usuarios.
2. El sistema verifica privilegios.
3. El administrador selecciona crear, modificar, desactivar o asignar rol.
4. El sistema solicita la información necesaria.
5. El administrador introduce los datos.
6. El sistema valida unicidad, formato, rol y ámbito.
7. El sistema muestra un resumen del cambio.
8. El administrador confirma.
9. El sistema aplica el cambio.
10. El sistema registra la auditoría.
11. Finaliza el caso de uso.

## 7. Flujos alternos

### FA-01 — Asignar ámbito por centro

El administrador asigna uno o más centros permitidos. El sistema valida que el ámbito sea compatible con el rol.

### FA-02 — Desactivar usuario

El sistema desactiva el acceso sin eliminar el historial de acciones realizadas.

### FA-03 — Restablecer acceso

El administrador inicia el proceso autorizado de recuperación sin visualizar contraseñas.

## 8. Flujos de excepción

### FE-01 — Rol inexistente

El sistema rechaza la asignación y muestra roles válidos.

### FE-02 — Ámbito incompatible

El sistema rechaza la combinación de rol y centro.

### FE-03 — Usuario duplicado

El sistema informa que el identificador ya existe.

### FE-04 — Intento de elevar privilegios

El sistema rechaza que un administrador se asigne capacidades superiores a las autorizadas.

## 9. Reglas provisionales

- `RN-CU18-01`: se aplica mínimo privilegio.
- `RN-CU18-02`: las contraseñas nunca se almacenan en texto plano.
- `RN-CU18-03`: desactivar no elimina historial.
- `RN-CU18-04`: cada cambio de acceso queda auditado.
- `RN-CU18-05`: un usuario no puede elevar sus propios privilegios.
- `RN-CU18-06`: los permisos se evalúan por rol y ámbito.

## 10. Requisitos relacionados

- `RF-17` Administrar usuarios, roles y ámbitos de acceso.
- `RNF-18` Control de acceso y auditoría.
- `RN-18` Mínimo privilegio.

## 11. Escenarios candidatos

- `ESC-CU18-01` Crear usuario farmacéutico.
- `ESC-CU18-02` Asignar ámbito por centro.
- `ESC-CU18-03` Desactivar usuario.
- `ESC-CU18-04` Rechazar elevación de privilegios.

## 12. Criterios de aceptación preliminares

- Solo administradores autorizados gestionan accesos.
- Los roles y ámbitos se validan.
- Los cambios quedan auditados.
- Desactivar preserva historial.
- No se almacenan secretos en texto plano.
- No existe autoelevación de privilegios.
