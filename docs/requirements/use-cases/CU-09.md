# CU-09 — Sincronizar inventario con fuente externa

**Versión:** 0.1
**Estado:** Borrador en refinamiento
**Clasificación:** Caso de uso funcional candidato
**Fuente:** `CU-05`, `SRC-11`, `SRC-12`, decisión de integración SALMI

## 1. Objetivo

Incorporar datos de inventario desde una fuente externa autorizada mediante un adaptador desacoplado, preservando procedencia, versión, errores y conflictos.

## 2. Actores

- **Actor principal:** `ACT-01 Administrador del sistema`.
- **Actor secundario:** `EXT-01 SALMI` u otra fuente externa autorizada.
- **Componente intermediario:** Adaptador de integración de DeepPharma.

El adaptador es un componente interno, no un actor.

## 3. Disparador

- Ejecución programada de sincronización.
- Solicitud manual de un administrador autorizado.
- Evento o disponibilidad anunciada por la fuente externa, si el contrato lo soporta.

## 4. Precondiciones

- Existe una fuente configurada.
- Existe un adaptador compatible.
- El contrato técnico y las credenciales están autorizados.
- El esquema de mapeo está versionado.
- La fuente está disponible o se puede detectar su indisponibilidad.

## 5. Postcondiciones

### Éxito

- Se registra la ejecución de sincronización.
- Los registros válidos quedan disponibles para validación.
- Se conserva la fuente, versión y fecha.
- Los registros rechazados quedan identificados.

### Fallo

- No se sobrescribe silenciosamente el inventario válido.
- Se registra el error y la fuente afectada.
- Los datos no confirmados permanecen en estado no aprobado.

## 6. Flujo básico

1. El sistema inicia o el administrador solicita la sincronización.
2. El sistema identifica la fuente y el adaptador.
3. El adaptador autentica la conexión autorizada.
4. El adaptador solicita los datos según el contrato.
5. El sistema registra la respuesta y metadatos.
6. El sistema transforma la respuesta al esquema interno sin aprobarla automáticamente.
7. El sistema ejecuta o solicita `CU-07`.
8. El sistema registra resultados válidos y rechazados.
9. El sistema informa el resumen de sincronización.
10. Finaliza el caso de uso.

## 7. Flujos alternos

### FA-01 — Sincronización incremental

El adaptador solicita únicamente cambios desde la última sincronización válida. El sistema registra el cursor, período o versión utilizado.

### FA-02 — Sincronización completa

El administrador solicita una carga completa. El sistema valida duplicados, versiones y conflictos antes de incorporar datos.

### FA-03 — Fuente simulada

El sistema utiliza un adaptador simulado con datos autorizados para desarrollo o demostración. La ejecución queda marcada como simulada.

## 8. Flujos de excepción

### FE-01 — Contrato no disponible

El sistema bloquea la integración y registra que SALMI carece de contrato técnico autorizado.

### FE-02 — Autenticación fallida

El sistema registra el fallo sin revelar credenciales y no incorpora datos.

### FE-03 — Fuente no disponible

El sistema registra timeout o indisponibilidad y mantiene el último estado válido identificado como desactualizado.

### FE-04 — Respuesta incompatible

El sistema rechaza la respuesta, registra diferencias de esquema y solicita revisión del adaptador.

### FE-05 — Conflicto de datos

El sistema identifica registros que contradicen datos existentes y los deja pendientes de resolución según una política explícita.

## 9. Reglas provisionales

- `RN-CU09-01`: toda fuente externa debe tener procedencia y contrato documentados.
- `RN-CU09-02`: SALMI no se acopla directamente al dominio interno.
- `RN-CU09-03`: una fuente simulada debe identificarse como simulada.
- `RN-CU09-04`: datos sincronizados no se consideran válidos hasta completar `CU-07`.
- `RN-CU09-05`: los secretos se gestionan fuera del código y no se registran en logs.
- `RN-CU09-06`: una sincronización fallida no elimina el último dato válido.

## 10. Requisitos relacionados

- `RF-09` Sincronizar inventario mediante adaptadores de fuentes externas autorizadas.
- `RNF-09` Tolerar indisponibilidad y registrar errores de integración.
- `RN-09` Mantener desacoplamiento y procedencia.

## 11. Escenarios candidatos

- `ESC-CU09-01` Sincronización completa exitosa.
- `ESC-CU09-02` Sincronización incremental exitosa.
- `ESC-CU09-03` Uso del adaptador simulado.
- `ESC-CU09-04` Fuente externa no disponible.
- `ESC-CU09-05` Respuesta incompatible.

## 12. Criterios de aceptación preliminares

- La integración utiliza un adaptador.
- SALMI puede sustituirse sin modificar la lógica de dominio.
- Los datos sincronizados pasan por validación.
- Las ejecuciones simuladas se identifican.
- Los errores no exponen secretos.
- La indisponibilidad no provoca pérdida de datos válidos.
