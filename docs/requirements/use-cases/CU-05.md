# CU-05 — Gestionar inventario en tiempo real

**Versión:** 0.1
**Estado:** Borrador en refinamiento
**Clasificación:** Caso de uso funcional principal
**Fuente académica:** `SRC-01`, `SRC-05`, `SRC-07`, `SRC-08`

## 1. Objetivo

Permitir que un farmacéutico o administrador de farmacia registre y consulte el estado actual del inventario, manteniendo la integridad de los datos y habilitando la detección de condiciones operativas relevantes.

## 2. Actores

- **Actor principal:** `ACT-02 Farmacéutico`.
- **Actor secundario:** `ACT-05 Administrador de farmacia`.
- **Actor administrativo:** `ACT-01 Administrador del sistema`, cuando corresponda.
- **Sistema externo relacionado:** `EXT-01 SALMI`, mediante adaptador sujeto a contrato.

## 3. Disparador

El actor autorizado necesita registrar una actualización o consultar el inventario actual de un medicamento en un centro de salud.

## 4. Precondiciones

- El actor está autenticado y autorizado.
- El medicamento está identificado en el catálogo permitido.
- El centro de salud está registrado.
- El sistema está disponible.
- Las unidades y reglas de validación están configuradas.

## 5. Postcondiciones

### Éxito

- La actualización queda registrada con actor, fecha y fuente.
- El inventario actual refleja el último dato válido.
- Se conserva el historial de cambios.
- El sistema puede recalcular cobertura y riesgo operativo.
- Una condición crítica puede activar `CU-16`.

### Fallo

- El inventario anterior válido no se sobrescribe.
- El sistema informa el motivo del rechazo.
- El intento queda registrado cuando corresponda.

## 6. Flujo básico — Registrar actualización

1. El actor solicita actualizar el inventario.
2. El sistema muestra el formulario de actualización.
3. El actor selecciona medicamento y centro de salud.
4. El actor introduce cantidad, fecha, unidad y observaciones cuando correspondan.
5. El sistema valida la identidad de las referencias.
6. El sistema valida tipos, rangos, unidad y fecha.
7. El sistema registra la actualización y su procedencia.
8. El sistema actualiza el inventario actual.
9. El sistema calcula o solicita recalcular días de cobertura.
10. El sistema evalúa si existe una condición operativa crítica.
11. El sistema muestra el resultado.
12. Finaliza el caso de uso.

## 7. Flujo alterno — Consultar inventario

1. El actor solicita consultar inventario.
2. El sistema solicita filtros disponibles.
3. El actor selecciona centro, medicamento, fecha o estado.
4. El sistema recupera los datos autorizados.
5. El sistema muestra cantidad, fecha, fuente y estado de actualización.
6. Finaliza el caso de uso.

## 8. Flujo alterno — Sincronizar fuente externa

1. Un adaptador autorizado recibe datos de `EXT-01`.
2. El sistema identifica la fuente y versión.
3. El sistema valida el esquema y la procedencia.
4. El sistema registra los datos recibidos.
5. El sistema actualiza únicamente registros válidos.
6. El sistema informa conflictos o registros rechazados.

La integración real con SALMI permanece condicionada a un contrato técnico autorizado.

## 9. Flujos de excepción

### FE-01 — Medicamento inexistente

1. El sistema informa que el medicamento no está registrado.
2. No registra la actualización.
3. El actor debe solicitar la administración del catálogo por el canal correspondiente.

### FE-02 — Centro de salud inexistente

1. El sistema informa que el centro no está registrado.
2. No registra la actualización.

### FE-03 — Cantidad inválida

1. El sistema rechaza valores negativos, no numéricos o incompatibles con la unidad.
2. Informa el campo y la regla incumplida.
3. Permite corregir la entrada.

### FE-04 — Fecha inválida

1. El sistema rechaza una fecha incompatible con la operación.
2. Informa la regla correspondiente.

### FE-05 — Conflicto de concurrencia

1. El sistema detecta que el registro cambió desde la consulta del actor.
2. No sobrescribe silenciosamente el dato.
3. Muestra el valor más reciente y solicita una decisión autorizada.

### FE-06 — Fuente externa no disponible

1. El sistema registra el fallo del adaptador.
2. Mantiene el último inventario válido identificado como vigente o desactualizado.
3. Informa la indisponibilidad.

## 10. Reglas de negocio provisionales

- `RN-CU05-01`: no se aceptan cantidades negativas.
- `RN-CU05-02`: cada actualización conserva actor, fuente y fecha.
- `RN-CU05-03`: un dato nuevo no elimina el historial.
- `RN-CU05-04`: datos manuales y externos deben identificarse por fuente.
- `RN-CU05-05`: los conflictos de concurrencia no se resuelven mediante sobrescritura silenciosa.
- `RN-CU05-06`: los umbrales de riesgo permanecen sujetos a las hipótesis `HIP-01` y `HIP-02`.
- `RN-CU05-07`: la integración con SALMI se realiza mediante adaptador desacoplado.

## 11. Requisitos relacionados

- `RF-05` Registrar y consultar inventario actual.
- `RNF-05` Reflejar una actualización dentro del tiempo aprobado `[PENDIENTE DE MEDICIÓN]`.
- `RN-05` Mantener integridad, procedencia e historial del inventario.

## 12. Escenarios candidatos

- `ESC-CU05-01` Registrar actualización válida.
- `ESC-CU05-02` Rechazar cantidad negativa.
- `ESC-CU05-03` Consultar inventario por centro y medicamento.
- `ESC-CU05-04` Resolver conflicto de concurrencia.
- `ESC-CU05-05` Recibir datos mediante adaptador externo.

## 13. Criterios de aceptación preliminares

- El farmacéutico puede registrar una actualización válida.
- El sistema rechaza datos inválidos con mensajes accionables.
- Se conserva historial y procedencia.
- Las consultas muestran fecha y estado de actualización.
- Los conflictos no producen pérdida silenciosa de datos.
- SALMI no se trata como dependencia directa del dominio.
- Las condiciones críticas quedan disponibles para el proceso de alertas.
