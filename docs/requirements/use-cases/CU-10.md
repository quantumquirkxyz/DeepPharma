# CU-10 — Evaluar modelos predictivos

**Versión:** 0.1
**Estado:** Borrador en refinamiento
**Clasificación:** Caso de uso funcional candidato
**Fuente:** `CU-02`, `SRC-08`, `SRC-15`, prácticas de reproducibilidad ML

## 1. Objetivo

Evaluar uno o más modelos entrenados mediante métricas, validación temporal y análisis de errores, produciendo evidencia para decidir si un modelo puede ser recomendado para aprobación.

## 2. Actores

- **Actor principal:** `ACT-03 Ingeniero de Machine Learning`.
- **Actor secundario:** `ACT-01 Administrador del sistema`.

## 3. Disparador

El ingeniero solicita evaluar un modelo o un conjunto de modelos entrenados.

## 4. Precondiciones

- Existe un modelo entrenado.
- Existe un conjunto de evaluación separado.
- La variable objetivo está definida.
- Las métricas y criterios están configurados.
- La evaluación puede reproducirse con la configuración registrada.

## 5. Postcondiciones

### Éxito

- Se registran métricas y parámetros de evaluación.
- Se registran errores, matrices o gráficos pertinentes.
- Se genera un reporte reproducible.
- El modelo queda `evaluado`, pero no necesariamente `aprobado`.

### Fallo

- La evaluación queda marcada como incompleta o inválida.
- No se recomienda el modelo con evidencia insuficiente.

## 6. Flujo básico

1. El ingeniero selecciona un modelo entrenado.
2. El sistema identifica el dataset y configuración asociados.
3. El sistema verifica separación entre entrenamiento y evaluación.
4. El sistema ejecuta predicciones sobre el conjunto de evaluación.
5. El sistema calcula métricas primarias y secundarias.
6. El sistema analiza errores y casos límite.
7. El sistema verifica posibles fugas de información.
8. El sistema compara resultados contra criterios aprobados.
9. El sistema genera el reporte.
10. El sistema registra el estado del modelo.
11. Finaliza el caso de uso.

## 7. Flujos alternos

### FA-01 — Comparar modelos

El ingeniero selecciona varios modelos compatibles. El sistema calcula métricas comparables y presenta diferencias, supuestos y limitaciones.

### FA-02 — Evaluación por segmento

El ingeniero solicita resultados por centro, medicamento, región o período. El sistema registra el alcance y advierte cuando el tamaño de muestra es insuficiente.

### FA-03 — Evaluación de calibración

El sistema calcula la correspondencia entre probabilidades predichas y frecuencias observadas cuando el modelo produzca probabilidades.

## 8. Flujos de excepción

### FE-01 — Dataset de evaluación inválido

El sistema rechaza la evaluación y registra la causa.

### FE-02 — Fuga de información detectada

El sistema invalida el reporte y bloquea la recomendación del modelo.

### FE-03 — Métricas no calculables

El sistema informa etiquetas faltantes, clases ausentes o datos insuficientes.

### FE-04 — Desempeño inferior al criterio

El sistema registra los resultados como no aprobados y documenta las limitaciones.

## 9. Reglas provisionales

- `RN-CU10-01`: las métricas deben calcularse sobre datos no utilizados indebidamente durante entrenamiento.
- `RN-CU10-02`: las métricas deben conservar dataset, versión y configuración.
- `RN-CU10-03`: ningún modelo se aprueba únicamente por una métrica.
- `RN-CU10-04`: los resultados agregados no deben ocultar fallos importantes por segmento.
- `RN-CU10-05`: el criterio primario debe definirse antes de comparar resultados.
- `RN-CU10-06`: una métrica sin evidencia reproducible no se considera resultado válido.

## 10. Requisitos relacionados

- `RF-10` Producir reportes de evaluación de modelos predictivos.
- `RNF-10` Reproducibilidad del reporte.
- `RN-10` No promover modelos sin evidencia suficiente.

## 11. Escenarios candidatos

- `ESC-CU10-01` Evaluación exitosa de un modelo.
- `ESC-CU10-02` Comparación de modelos candidatos.
- `ESC-CU10-03` Detección de fuga de información.
- `ESC-CU10-04` Desempeño insuficiente.
- `ESC-CU10-05` Métricas por segmento.

## 12. Criterios de aceptación preliminares

- El reporte identifica modelo, dataset, versión y configuración.
- Las métricas se calculan sobre un conjunto válido.
- Las fugas de información invalidan la evaluación.
- Se reportan limitaciones y tamaños de muestra.
- La evaluación no equivale automáticamente a aprobación.
