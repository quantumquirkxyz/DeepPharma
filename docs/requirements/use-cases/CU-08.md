# CU-08 — Preprocesar datos históricos

**Versión:** 0.1
**Estado:** Borrador en refinamiento
**Clasificación:** Caso de uso funcional candidato
**Fuente:** `CU-07`, `CU-02`, `SRC-08`, reglas de reproducibilidad de datos

## 1. Objetivo

Transformar un conjunto validado en una versión reproducible y apta para análisis o entrenamiento, conservando las decisiones aplicadas y la relación con los datos originales.

## 2. Actores

- **Actor principal:** `ACT-03 Ingeniero de Machine Learning`.
- **Actor secundario:** `ACT-01 Administrador del sistema`.

## 3. Disparador

El ingeniero solicita preprocesar un conjunto validado con una configuración aprobada.

## 4. Precondiciones

- Existe un conjunto en estado `validado`.
- La configuración de transformación está definida.
- Las herramientas de procesamiento están disponibles.
- La estrategia para nulos, duplicados y valores atípicos está documentada.

## 5. Postcondiciones

### Éxito

- Se crea una versión del conjunto procesado.
- Se registran transformaciones, parámetros y procedencia.
- Se conserva la relación con el conjunto original.
- El resultado queda disponible para `CU-02`.

### Fallo

- No se publica un resultado incompleto como conjunto apto.
- Se registra el error y el paso afectado.
- El conjunto original permanece sin modificar.

## 6. Flujo básico

1. El actor selecciona un conjunto validado.
2. El sistema muestra la configuración disponible.
3. El actor confirma la configuración.
4. El sistema crea un identificador de ejecución.
5. El sistema aplica limpieza y transformación según la configuración.
6. El sistema genera variables derivadas aprobadas.
7. El sistema aplica la estrategia de partición o preparación definida.
8. El sistema verifica que no se introduzca información futura.
9. El sistema registra parámetros, versión y métricas.
10. El sistema almacena el conjunto procesado.
11. El sistema presenta el resultado.
12. Finaliza el caso de uso.

## 7. Flujos alternos

### FA-01 — Configuración personalizada

El actor selecciona parámetros permitidos. El sistema valida la configuración y la registra junto con la ejecución.

### FA-02 — Reprocesamiento

El actor solicita reprocesar una versión con una nueva configuración. El sistema crea una nueva versión sin sobrescribir la anterior.

### FA-03 — Generación de subconjunto

El actor selecciona período, centro o medicamento. El sistema registra el alcance y la relación con el conjunto padre.

## 8. Flujos de excepción

### FE-01 — Conjunto no validado

El sistema bloquea la operación y solicita completar `CU-07`.

### FE-02 — Transformación inválida

El sistema detecta que una transformación produce valores incompatibles y rechaza la ejecución.

### FE-03 — Fuga de información

El sistema detecta uso de información futura o parámetros calculados con datos de prueba y marca el resultado como inválido.

### FE-04 — Resultado vacío o insuficiente

El sistema informa que el resultado no contiene información suficiente para el propósito seleccionado.

## 9. Reglas provisionales

- `RN-CU08-01`: el conjunto original no se modifica.
- `RN-CU08-02`: toda transformación debe estar versionada.
- `RN-CU08-03`: las transformaciones deben poder reproducirse.
- `RN-CU08-04`: los parámetros aprendidos se ajustan únicamente con datos permitidos por la estrategia temporal.
- `RN-CU08-05`: una transformación no debe usar información futura.
- `RN-CU08-06`: el balanceo de clases, imputación y normalización deben justificarse y documentarse.
- `RN-CU08-07`: la versión procesada debe conservar procedencia del conjunto original.

## 10. Requisitos relacionados

- `RF-08` Generar versiones reproducibles de datos preprocesados.
- `RNF-08` Reproducibilidad del procesamiento.
- `RN-08` Preservar versiones y transformaciones.

## 11. Escenarios candidatos

- `ESC-CU08-01` Preprocesamiento reproducible exitoso.
- `ESC-CU08-02` Bloqueo por conjunto no validado.
- `ESC-CU08-03` Rechazo por fuga de información.
- `ESC-CU08-04` Reprocesamiento con nueva versión.

## 12. Criterios de aceptación preliminares

- Solo se procesan conjuntos validados.
- El conjunto original permanece inmutable.
- Cada transformación queda registrada.
- El resultado puede reproducirse con la misma configuración.
- Se detecta y bloquea el uso indebido de información futura.
- La versión procesada puede rastrearse hasta la fuente original.
