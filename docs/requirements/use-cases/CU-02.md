# CU-02 — Entrenar y evaluar modelos de aprendizaje automático

**Versión:** 0.1
**Estado:** Borrador en refinamiento
**Clasificación:** Caso de uso funcional principal
**Fuente académica:** `SRC-01`, `SRC-05`, `SRC-07`, `SRC-08`

## 1. Objetivo

Permitir que un ingeniero de Machine Learning entrene, compare y registre modelos predictivos utilizando datos históricos validados, con una estrategia de evaluación reproducible.

## 2. Actores

- **Actor principal:** `ACT-03 Ingeniero de Machine Learning`.
- **Actor secundario:** `ACT-01 Administrador del sistema`.

## 3. Disparador

El ingeniero solicita ejecutar un entrenamiento con un conjunto de datos validado y una configuración de experimento.

## 4. Precondiciones

- Existe al menos un conjunto de datos validado.
- El esquema de datos está disponible.
- Las variables objetivo y predictoras están definidas.
- La configuración del experimento es válida.
- El entorno de entrenamiento está disponible.

## 5. Postcondiciones

### Éxito

- Se registra el experimento.
- Se entrenan los modelos candidatos configurados.
- Se registran métricas y parámetros.
- Se identifica el modelo recomendado según el criterio aprobado.
- El modelo queda en estado `evaluado` o `pendiente de aprobación`.

### Fallo

- El experimento queda registrado como fallido.
- No se promociona un modelo incompleto.
- Se conserva el motivo del fallo y la evidencia disponible.

## 6. Flujo básico

1. El ingeniero solicita entrenar modelos.
2. El sistema muestra los conjuntos validados disponibles.
3. El ingeniero selecciona el conjunto y la configuración del experimento.
4. El sistema valida que el conjunto sea apto para entrenamiento.
5. El sistema crea un identificador de experimento.
6. El sistema separa los datos respetando el orden temporal.
7. El sistema entrena los modelos candidatos.
8. El sistema evalúa cada modelo en el conjunto de prueba.
9. El sistema registra parámetros, métricas, versión y procedencia.
10. El sistema compara los resultados con los criterios aprobados.
11. El sistema presenta el modelo recomendado y sus limitaciones.
12. Finaliza el caso de uso.

## 7. Flujos alternos

### FA-01 — Seleccionar un único modelo

El ingeniero puede seleccionar un subconjunto de modelos candidatos cuando el objetivo del experimento lo justifique. El sistema registra la selección y conserva la comparabilidad del experimento.

### FA-02 — Solicitar evaluación adicional

El ingeniero solicita métricas o análisis adicionales. El sistema los ejecuta y los agrega al registro del experimento.

### FA-03 — Solicitar aprobación del modelo recomendado

El ingeniero solicita que el modelo recomendado pase a revisión o aprobación. El sistema cambia el estado, pero no lo habilita automáticamente para producción.

## 8. Flujos de excepción

### FE-01 — Datos no validados

1. El sistema rechaza el entrenamiento.
2. Informa que el conjunto debe completar `CU-07`.
3. Registra el intento.

### FE-02 — Esquema incompatible

1. El sistema identifica variables faltantes o incompatibles.
2. Registra el error.
3. Solicita corregir la configuración o el conjunto.

### FE-03 — Fuga de información

1. El sistema detecta una variable o transformación incompatible con la separación temporal.
2. Marca el experimento como inválido.
3. Impide registrar el resultado como modelo aprobado.

### FE-04 — Desempeño insuficiente

1. El sistema informa que ningún modelo cumple el criterio aprobado.
2. Registra las métricas obtenidas.
3. Mantiene los modelos como no aprobados.

### FE-05 — Error de entrenamiento

1. El sistema registra el error técnico.
2. Conserva el estado parcial únicamente como evidencia de experimento.
3. Informa al ingeniero.

## 9. Reglas de negocio provisionales

- `RN-CU02-01`: solo se entrenan modelos con datos validados.
- `RN-CU02-02`: la evaluación debe respetar el orden temporal.
- `RN-CU02-03`: el experimento debe registrar dataset, versión, configuración y semillas.
- `RN-CU02-04`: ningún modelo se considera aprobado solo por obtener la métrica más alta.
- `RN-CU02-05`: la métrica primaria y sus umbrales deben estar aprobados antes del entrenamiento.
- `RN-CU02-06`: un resultado reproducible debe poder volver a ejecutarse con la misma configuración.

## 10. Requisitos relacionados

- `RF-02` Entrenar y evaluar modelos con datos históricos validados.
- `RNF-02` Tiempo máximo de entrenamiento `[PENDIENTE DE MEDICIÓN]`.

## 11. Escenarios candidatos

- `ESC-CU02-01` Entrenamiento reproducible con datos válidos.
- `ESC-CU02-02` Rechazo por fuga de información.
- `ESC-CU02-03` Ningún modelo alcanza el criterio mínimo.
- `ESC-CU02-04` Registro de un modelo recomendado pendiente de aprobación.

## 12. Criterios de aceptación preliminares

- Solo se utilizan conjuntos validados.
- La separación temporal es visible y reproducible.
- Se registran parámetros, métricas, versiones y procedencia.
- Un modelo con desempeño insuficiente no se promociona.
- Una fuga de información invalida el experimento.
- Los resultados pueden ser revisados por el ingeniero.
