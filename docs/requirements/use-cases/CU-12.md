# CU-12 — Consultar explicación de una predicción

**Versión:** 0.1
**Estado:** Borrador en refinamiento
**Clasificación:** Caso de uso funcional candidato
**Fuente:** `CU-03`, `CU-04`, prácticas de explicabilidad ML

## 1. Objetivo

Permitir que un usuario autorizado consulte los factores y metadata asociados a una predicción, sin presentar la explicación como una prueba causal ni como una garantía de resultado.

## 2. Actores

- **Actor principal:** `ACT-02 Farmacéutico`.
- **Actores secundarios:** `ACT-05 Administrador de farmacia`, `ACT-03 Ingeniero de Machine Learning`.

## 3. Disparador

El actor selecciona una predicción o alerta y solicita consultar su explicación.

## 4. Precondiciones

- Existe una predicción registrada.
- La predicción conserva modelo, versión y fecha.
- El actor tiene permiso para consultar el resultado.
- Existe una explicación calculada o se puede generar con el método aprobado.

## 5. Postcondiciones

### Éxito

- El actor visualiza factores relevantes, valores y metadata.
- La explicación queda relacionada con la predicción específica.
- Se muestran limitaciones y fecha de cálculo.

### No disponible

- El sistema informa que no existe explicación para esa versión.
- La predicción no se presenta como incompleta por esa sola razón.

## 6. Flujo básico

1. El actor selecciona una predicción.
2. El sistema verifica permisos.
3. El sistema recupera modelo, versión, fecha y datos relevantes.
4. El sistema recupera o calcula la explicación.
5. El sistema muestra factores relevantes y sus valores.
6. El sistema muestra advertencias sobre interpretación.
7. Finaliza el caso de uso.

## 7. Flujos alternos

### FA-01 — Explicación global

El ingeniero solicita información general sobre variables relevantes del modelo. El sistema muestra el alcance y dataset de referencia.

### FA-02 — Explicación local

El usuario solicita la explicación de una predicción individual. El sistema la relaciona exclusivamente con esa ejecución.

### FA-03 — Consultar metadata

El usuario solicita versión del modelo, fecha, fuente de datos y horizonte. El sistema muestra la metadata autorizada.

## 8. Flujos de excepción

### FE-01 — Predicción inexistente

El sistema informa que no encuentra la predicción y no genera una explicación inventada.

### FE-02 — Modelo retirado

El sistema permite consultar la explicación histórica si existe y muestra que el modelo ya no está habilitado.

### FE-03 — Explicación no reproducible

El sistema marca la explicación como no disponible o limitada y registra la causa.

### FE-04 — Datos sensibles

El sistema oculta información no autorizada antes de presentar la explicación.

## 9. Reglas provisionales

- `RN-CU12-01`: una explicación no demuestra causalidad.
- `RN-CU12-02`: la explicación debe referenciar predicción y versión de modelo.
- `RN-CU12-03`: los factores mostrados no pueden inventarse cuando no existe evidencia calculada.
- `RN-CU12-04`: se deben mostrar limitaciones del método.
- `RN-CU12-05`: la explicación no sustituye el criterio profesional del farmacéutico.

## 10. Requisitos relacionados

- `RF-12` Mostrar explicaciones disponibles de predicciones con su modelo y versión.
- `RNF-12` Transparencia y trazabilidad de resultados.
- `RN-12` No presentar explicaciones como causalidad.

## 11. Escenarios candidatos

- `ESC-CU12-01` Consultar explicación local.
- `ESC-CU12-02` Consultar metadata del modelo.
- `ESC-CU12-03` Predicción con modelo retirado.
- `ESC-CU12-04` Explicación no disponible.

## 12. Criterios de aceptación preliminares

- La explicación está asociada a una predicción concreta.
- Se identifica el modelo y versión utilizados.
- Se muestran limitaciones.
- No se exponen datos no autorizados.
- El sistema no inventa explicaciones.
- La explicación no se presenta como relación causal.
