# CU-01 — Registrar datos históricos de inventario

**Versión:** 0.1
**Estado:** Borrador en refinamiento
**Clasificación:** Caso de uso funcional principal
**Fuente académica:** `SRC-01`, `SRC-04`, `SRC-05`, `SRC-07`

## 1. Nombre

Registrar datos históricos de inventario.

## 2. Objetivo

Permitir que un actor autorizado incorpore datos históricos de inventario para que DeepPharma los valide, registre y deje disponibles para el procesamiento posterior y el entrenamiento de modelos.

## 3. Actores

- **Actor principal:** `ACT-01 Administrador del sistema`.
- **Actor secundario:** `ACT-03 Ingeniero de Machine Learning`.
- **Fuente externa:** `EXT-02 Portal de Datos Abiertos de Panamá`.

La asignación se basa en responsabilidad: el administrador controla autorización, procedencia y versionado; el ingeniero de ML participa en la preparación posterior.

## 4. Disparador

El actor autorizado solicita registrar un conjunto de datos históricos mediante archivo o fuente externa configurada.

## 5. Precondiciones

- El actor está autenticado y autorizado.
- Existe un esquema de datos aprobado.
- La fuente o archivo está disponible.
- El sistema puede registrar la procedencia del conjunto.

## 6. Postcondiciones

### Éxito

- El conjunto de datos queda registrado con identificador y versión.
- La procedencia, período y fecha de carga quedan almacenados.
- El conjunto queda disponible para validación y/o preprocesamiento.
- Se informa el resultado al actor.

### Fallo

- No se incorpora un conjunto inválido como dato aprobado.
- Se registra el motivo del rechazo.
- El actor recibe información accionable para corregir el problema.

## 7. Flujo básico

1. El actor solicita registrar datos históricos.
2. El sistema muestra las fuentes o formatos disponibles.
3. El actor selecciona una fuente o carga un archivo autorizado.
4. El sistema registra metadatos de procedencia y versión.
5. El sistema verifica que el archivo pueda leerse.
6. El sistema identifica el esquema recibido.
7. El sistema registra el conjunto en estado pendiente de validación.
8. El sistema muestra el identificador y el estado del registro.
9. Finaliza el caso de uso.

## 8. Flujos alternos

### FA-01 — Seleccionar fuente externa

Se origina en el paso 3.

1. El actor selecciona una fuente externa configurada.
2. El sistema solicita o recupera el conjunto autorizado.
3. El sistema registra la procedencia.
4. Continúa en el paso 5 del flujo básico.

### FA-02 — Cancelar carga

Se origina antes de completar el paso 4.

1. El actor cancela la operación.
2. El sistema no registra el conjunto como incorporado.
3. Finaliza el caso de uso.

## 9. Flujos de excepción

### FE-01 — Formato no soportado

Se origina en el paso 5.

1. El sistema informa que el formato no es soportado.
2. El sistema identifica los formatos aceptados.
3. El conjunto no queda registrado como disponible.
4. Finaliza el caso de uso.

### FE-02 — Archivo ilegible o corrupto

Se origina en el paso 5.

1. El sistema informa que no puede leer el archivo.
2. El sistema registra el intento fallido.
3. El conjunto no queda disponible.
4. Finaliza el caso de uso.

### FE-03 — Metadatos insuficientes

Se origina en el paso 4.

1. El sistema identifica los metadatos faltantes.
2. El sistema solicita completarlos.
3. El actor corrige los datos o cancela la operación.

### FE-04 — Fuente externa no disponible

Se origina en FA-01, paso 2.

1. El sistema informa que no puede acceder a la fuente.
2. El sistema registra el error técnico.
3. El actor puede reintentar o cancelar.

## 10. Reglas de negocio provisionales

- `RN-CU01-01`: solo se aceptan fuentes autorizadas.
- `RN-CU01-02`: cada conjunto debe conservar procedencia y versión.
- `RN-CU01-03`: datos públicos, sintéticos e institucionales deben identificarse por separado.
- `RN-CU01-04`: un conjunto pendiente de validación no puede utilizarse como conjunto aprobado para entrenamiento.
- `RN-CU01-05`: los formatos iniciales quedan sujetos a `CL-08`; no se
  asume CSV/XLSX como decisión aprobada.
- `RN-CU01-06`: el período histórico queda sujeto a `CL-09`; 2019–2023 es una
  hipótesis de trabajo, no un hecho institucional.

- `ESC-CU01-01` Registrar un archivo histórico válido.
- `ESC-CU01-02` Rechazar un archivo con formato no soportado.
- `ESC-CU01-03` Registrar datos desde una fuente externa disponible.
- `ESC-CU01-04` Gestionar una fuente externa no disponible.

## 13. Criterios de aceptación preliminares

- El actor autorizado puede iniciar el registro.
- El sistema conserva procedencia, versión y período.
- Los archivos ilegibles o no soportados se rechazan con información accionable.
- Los datos pendientes de validación no se utilizan para entrenamiento.
- Cada resultado puede rastrearse hasta la fuente y la operación que lo registró.
