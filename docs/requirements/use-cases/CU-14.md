# CU-14 — Consultar detalle de alerta

**Versión:** 0.1
**Estado:** Borrador en refinamiento
**Clasificación:** Caso de uso funcional candidato
**Fuente:** `CU-03`, `CU-04`, `CU-12`, requisitos de trazabilidad

## 1. Objetivo

Permitir que un usuario autorizado consulte el contexto completo de una alerta, incluyendo predicción, inventario, nivel operativo, modelo y estado de gestión.

## 2. Actores

- **Actor principal:** `ACT-02 Farmacéutico`.
- **Actor secundario:** `ACT-05 Administrador de farmacia`.
- **Actor administrativo:** `ACT-01 Administrador del sistema`, según permisos.

## 3. Disparador

El actor selecciona una alerta desde la lista de `CU-04`.

## 4. Precondiciones

- La alerta existe.
- El actor tiene permiso sobre el medicamento y centro.
- La alerta conserva referencia a una predicción o condición operativa.

## 5. Postcondiciones

- El actor visualiza la información autorizada.
- La consulta queda registrada cuando la auditoría lo requiera.
- El sistema no modifica el estado de gestión por consultar el detalle.

## 6. Flujo básico

1. El actor selecciona una alerta.
2. El sistema verifica permisos.
3. El sistema recupera la alerta y sus referencias.
4. El sistema muestra medicamento, centro, nivel, fecha y estado.
5. El sistema muestra predicción y modelo utilizado.
6. El sistema muestra inventario y cobertura disponible.
7. El sistema muestra factores explicativos cuando existan.
8. El sistema muestra historial de gestión.
9. Finaliza el caso de uso.

## 7. Flujos alternos

### FA-01 — Consultar explicación

El actor solicita `CU-12`. El sistema abre la explicación vinculada a la misma predicción.

### FA-02 — Consultar historial

El actor solicita cambios de estado y acciones anteriores. El sistema los muestra en orden temporal.

### FA-03 — Exportar detalle

El actor solicita exportar el detalle. El sistema verifica permisos y genera el formato autorizado.

## 8. Flujos de excepción

### FE-01 — Alerta inexistente

El sistema informa que la alerta ya no está disponible o nunca existió.

### FE-02 — Referencia incompleta

El sistema muestra el detalle disponible y marca la información faltante, sin inventarla.

### FE-03 — Acceso no autorizado

El sistema rechaza la consulta y no revela información.

### FE-04 — Predicción desactualizada

El sistema muestra la antigüedad y estado de vigencia.

## 9. Reglas provisionales

- `RN-CU14-01`: consultar detalle no cambia el estado de gestión.
- `RN-CU14-02`: el detalle debe conservar referencia a predicción, modelo y fecha.
- `RN-CU14-03`: la información faltante se identifica explícitamente.
- `RN-CU14-04`: el acceso se limita al ámbito autorizado.
- `RN-CU14-05`: una explicación solo se muestra si existe evidencia calculada.

## 10. Requisitos relacionados

- `RF-13` Mostrar el detalle y la procedencia de una alerta.
- `RNF-14` Trazabilidad de la información presentada.
- `RN-14` No ocultar ni inventar datos de evidencia.

## 11. Escenarios candidatos

- `ESC-CU14-01` Consultar alerta con evidencia completa.
- `ESC-CU14-02` Consultar alerta con predicción desactualizada.
- `ESC-CU14-03` Consultar explicación vinculada.
- `ESC-CU14-04` Acceso fuera del ámbito autorizado.

## 12. Criterios de aceptación preliminares

- El detalle identifica la alerta y su origen.
- Predicción, modelo e inventario son distinguibles.
- Los datos desactualizados se indican.
- La consulta no muta la alerta.
- Las referencias faltantes no se inventan.

## 13. Pendientes

- Definir formato de historial.
- Definir permisos por rol y centro.
- Definir evidencia explicativa.
- Definir auditoría de consultas.
