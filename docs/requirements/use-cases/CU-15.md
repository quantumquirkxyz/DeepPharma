# CU-15 — Reconocer o gestionar una alerta

**Versión:** 0.1
**Estado:** Borrador en refinamiento
**Clasificación:** Caso de uso funcional candidato
**Fuente:** `CU-04`, `CU-14`, reglas de auditoría

## 1. Objetivo

Permitir que un usuario autorizado registre la revisión, reconocimiento o acción tomada frente a una alerta, conservando el resultado y la responsabilidad.

## 2. Actores

- **Actor principal:** `ACT-02 Farmacéutico`.
- **Actor secundario:** `ACT-05 Administrador de farmacia`.
- **Actor administrativo:** `ACT-01 Administrador del sistema`, según permisos.

## 3. Disparador

El actor consulta una alerta y selecciona una acción de gestión.

## 4. Precondiciones

- La alerta existe.
- La alerta pertenece al ámbito del actor.
- La acción solicitada está permitida.
- El estado actual admite la transición.

## 5. Postcondiciones

### Éxito

- La acción queda registrada.
- Se conserva actor, fecha, estado anterior, estado nuevo y observación.
- La alerta refleja el estado actualizado.
- El historial permanece disponible.

### Fallo

- La alerta conserva su estado anterior.
- No se registra una acción incompleta como válida.

## 6. Flujo básico

1. El actor abre el detalle de una alerta.
2. El sistema verifica permisos y estado.
3. El actor selecciona una acción.
4. El sistema solicita observación o información requerida.
5. El actor confirma la acción.
6. El sistema valida la transición.
7. El sistema registra actor, fecha, acción y observación.
8. El sistema actualiza el estado de gestión.
9. El sistema muestra la confirmación.
10. Finaliza el caso de uso.

## 7. Acciones candidatas

- `reconocer`;
- `en revisión`;
- `acción de reposición iniciada`;
- `resuelta`;
- `descartada con justificación`;
- `escalada`.

Los estados definitivos deberán aprobarse antes de implementarse.

## 8. Flujos alternos

### FA-01 — Escalar alerta

El actor remite la alerta a un responsable superior. El sistema conserva motivo, destinatario y fecha.

### FA-02 — Registrar acción externa

El actor registra una acción realizada fuera de DeepPharma, como una solicitud de reposición. El sistema no afirma que la compra se haya completado; solo registra la evidencia declarada.

### FA-03 — Resolver alerta

El actor registra la condición que permite cerrar la gestión. El sistema conserva la alerta histórica y no elimina la predicción original.

## 9. Flujos de excepción

### FE-01 — Transición inválida

El sistema rechaza el cambio porque el estado actual no permite la acción.

### FE-02 — Observación obligatoria ausente

El sistema solicita la información requerida y no confirma la acción.

### FE-03 — Alerta fuera de ámbito

El sistema rechaza la acción sin revelar información adicional.

### FE-04 — Conflicto concurrente

El sistema detecta que otro usuario modificó la alerta y solicita revisar el estado actualizado.

## 10. Reglas provisionales

- `RN-CU15-01`: reconocer una alerta no equivale a resolverla.
- `RN-CU15-02`: toda transición debe ser válida según la máquina de estados aprobada.
- `RN-CU15-03`: las acciones deben conservar actor y fecha.
- `RN-CU15-04`: cerrar una alerta no elimina su historial.
- `RN-CU15-05`: registrar una acción externa no demuestra que la acción institucional se completó.
- `RN-CU15-06`: las transiciones críticas requieren observación o evidencia.

## 11. Requisitos relacionados

- `RF-14` Registrar reconocimiento, escalamiento y resolución de alertas.
- `RNF-15` Auditoría de acciones.
- `RN-15` Mantener historial de gestión.

## 12. Escenarios candidatos

- `ESC-CU15-01` Reconocer una alerta.
- `ESC-CU15-02` Escalar una alerta.
- `ESC-CU15-03` Registrar solicitud de reposición externa.
- `ESC-CU15-04` Resolver una alerta.
- `ESC-CU15-05` Rechazar transición inválida.

## 13. Criterios de aceptación preliminares

- Solo actores autorizados pueden gestionar alertas.
- Las transiciones inválidas se rechazan.
- Las acciones quedan auditadas.
- Reconocer y resolver son estados distintos.
- El sistema no afirma que una acción externa ocurrió sin evidencia.
- El historial no se elimina.

## 14. Pendientes

- Definir máquina de estados.
- Definir acciones y transiciones.
- Definir roles autorizados por transición.
- Definir evidencia requerida.
- Definir concurrencia y auditoría.
