# CU-17 — Generar reportes de inventario y riesgo

**Versión:** 0.1
**Estado:** Borrador en refinamiento
**Clasificación:** Caso de uso funcional candidato
**Fuente:** `CU-04`, `CU-13`, requisitos de consulta y trazabilidad

## 1. Objetivo

Permitir que un usuario autorizado genere reportes reproducibles sobre inventario, predicciones y alertas dentro de su ámbito.

## 2. Actores

- **Actor principal:** `ACT-05 Administrador de farmacia`.
- **Actores secundarios:** `ACT-02 Farmacéutico`, `ACT-01 Administrador del sistema`.

## 3. Disparador

El actor solicita un reporte con filtros, período y formato definidos.

## 4. Precondiciones

- El actor está autenticado y autorizado.
- Existen datos para el período solicitado o el sistema puede informar ausencia.
- Los filtros son válidos.
- El formato solicitado está disponible.

## 5. Postcondiciones

### Éxito

- Se genera un reporte con parámetros, fecha y ámbito.
- El reporte conserva la fuente de sus datos.
- El resultado puede descargarse o consultarse según permisos.

### Sin datos

- El sistema genera un estado vacío o informa que no hay datos.
- No inventa registros ni métricas.

## 6. Flujo básico

1. El actor solicita generar un reporte.
2. El sistema muestra tipos y filtros disponibles.
3. El actor selecciona tipo, período, centro, medicamento y nivel cuando corresponda.
4. El sistema valida permisos y parámetros.
5. El sistema recupera datos autorizados.
6. El sistema calcula agregaciones permitidas.
7. El sistema genera el reporte.
8. El sistema incluye metadata, fuente y fecha de generación.
9. El sistema muestra o entrega el resultado.
10. Finaliza el caso de uso.

## 7. Tipos de reporte candidatos

- inventario actual;
- historial de inventario;
- alertas priorizadas;
- evolución de riesgo;
- predicciones por período;
- estado de gestión de alertas;
- calidad de datos;
- evaluación de modelos.

Los tipos definitivos se priorizarán según la rúbrica y el MVP.

## 8. Flujos alternos

### FA-01 — Exportar a archivo

El actor selecciona un formato autorizado. El sistema genera el archivo y registra la exportación.

### FA-02 — Reporte programado

El sistema genera el reporte según programación configurada y lo entrega a destinatarios autorizados.

### FA-03 — Comparar períodos

El actor solicita comparación. El sistema muestra diferencias y advierte sobre cambios de fuente, cobertura o modelo.

## 9. Flujos de excepción

### FE-01 — Parámetros inválidos

El sistema identifica filtros incompatibles, rangos inválidos o período no permitido.

### FE-02 — Acceso fuera del ámbito

El sistema rechaza la solicitud sin incluir información no autorizada.

### FE-03 — Datos desactualizados

El reporte muestra la antigüedad y estado de los datos.

### FE-04 — Error de generación

El sistema registra el error y no presenta un archivo incompleto como válido.

## 10. Reglas provisionales

- `RN-CU17-01`: el reporte conserva filtros, período, fuente y fecha.
- `RN-CU17-02`: el reporte respeta permisos y ámbito.
- `RN-CU17-03`: los datos faltantes se identifican, no se rellenan sin regla aprobada.
- `RN-CU17-04`: los reportes de modelo incluyen versión y dataset.
- `RN-CU17-05`: una exportación no concede permisos adicionales.

## 12. Escenarios candidatos

- `ESC-CU17-01` Reporte de alertas por centro.
- `ESC-CU17-02` Reporte de inventario por período.
- `ESC-CU17-03` Reporte sin datos.
- `ESC-CU17-04` Exportación autorizada.
- `ESC-CU17-05` Rechazo por ámbito.

## 13. Criterios de aceptación preliminares

- El reporte refleja los filtros seleccionados.
- El reporte incluye fuente y fecha.
- No contiene datos fuera del ámbito.
- Los datos desactualizados se identifican.
- Los resultados son reproducibles con los mismos parámetros.
